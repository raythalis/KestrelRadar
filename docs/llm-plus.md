# LLM+ 判定模式

LLM+ 不负责采集，也不直接发送通知。它是在**关键词和本地打分之后，必要时请模型再看一次内容**。例如你关注“诺兰的新电影预告”：标题虽然命中“诺兰”，模型仍可判断它只是旧片回顾，而不是你要的预告。想先了解分数线，见[判定与打分](judgment-scoring.md)；操作步骤见[使用手册](usage.md)。

## 怎样启用

先到**模型**页添加供应商，选择模型并保存调用顺序（最多三个）；再到**设置 → 判定**选择 LLM+。监听选“跟随全局”时使用全局模式，也可为该监听单独选“纯算法”或“LLM+”。全局默认是纯算法；**只添加供应商，并不会自动让内容交给模型**。可以填写意图描述，说明真正关注的内容含义；它只在 LLM+ 下生效。

模型清单需要从供应商接口读取，无法取得清单的模型不会出现在可选项中。判定请求需要供应商提供兼容接口；例如 Ollama 也需开启兼容接口。API Key 保存后不会在读取接口明文显示。具体配置见[配置](configuration.md)。

## 哪些内容会调用模型

首先检查排除词、包含关键词和分数。**被排除词、关键词门槛或低分线挡下的内容，不调用模型。**其余情况分两种：

- **写了意图描述**：只要本地规则已经放行，就让模型判断是否符合意图；高分内容也会判断。比如“诺兰的新电影预告”可排除只提到他名字的旧片回顾。
- **没有意图描述**：填了关键词而分数处于高低分线之间的灰区，才请模型复核；高分直接通过。如果关键词和意图都没填，则按中性 50 分放行，**不调用模型**。

纯算法模式永远不请求模型，灰区会保守放行。模型通过时内容保留，否决时不通过。一个条目对一条监听只会留下一个最终判定；但失败重试可能造成多次模型请求。发现卡的“测试采集”只测来源，不会触发判定模型；修改已保存的监听规则也不会自动重判已有判定的旧条目。当前界面没有规则预览入口；后端虽有只算本地规则的预览接口，但不调模型，也不保存最终判定。

## 模型看什么

每次模型判定只发送**标题、摘要**，以及你填写的**关注意图**（如果有）；请求还包含固定的简短判定要求。**不会读取网页正文，也不会把正文发给模型判断。**因此，如果关键事实只在正文里、标题和摘要没有提到，模型可能无法作出符合你预期的判断；摘要为空时也不会额外抓取正文来补齐。

## 请求失败时怎么办

系统按你在**模型**页保存的顺序尝试。单次请求超时、供应商报错或回复不符合要求，都算失败；先按“模型失败重试次数”对**同一模型**额外重试，仍失败才轮到下一个。默认额外重试 1 次，也就是每个模型最多请求 2 次；填 0 就不在同一模型上重试，但仍可能尝试下一模型。任一个模型成功即停止。

全部模型失败，或没有可用模型时，会记下异常，再按**设置 → 判定 → 模型不可用时**处理：

- **降级到纯算法（默认）**：沿用本地规则原本的放行结果，即使内容处于灰区，仍可能进入事件与后续动作；这并不代表模型给了肯定回答。
- **本次不作判定**：不留下这条内容对该监听的判定结果，等以后采集时再尝试；不是将它判为不通过。没有通过判定前它不会形成新事件。当前界面中的这个选项若显示为“丢弃”，容易误解；这里描述的是现有实际行为。

## 何时可能产生费用

只有上述需要模型判断的内容才会发出判定模型请求；纯算法、前置门槛未通过、低分内容和“测试采集”不会产生判定模型请求。供应商是否收费、如何计费，以其价格为准；Kestrel Radar 不提供模型费用上限或预估账单。

**Token 粗估**：一条实际调用模型的判定通常是短请求。若标题约 20～50 个汉字、摘要约 100～300 个汉字，且关注意图不长，可先按**每次请求约 200～800 个输入 token，另加约 20～100 个输出 token**估算；这是预算用的宽松量级，**不是 Kestrel Radar 实测或供应商承诺**。摘要或意图更长、模型分词方式不同，都会改变用量；不同模型还可能额外计入推理 token。粗略预算可用“预计实际模型调用次数 × 单次输入、输出 token × 供应商各自单价”计算，并给重试留余量；不进入模型判定的内容无需算这一项。

**失败的请求也可能收费**：超时或格式不正确时供应商可能已经处理了请求；重试与切换模型会增加调用次数。即使最终降级或本次不作判定，已经发出的请求仍可能计费。自托管本地模型没有远程 API 账单，但会使用自己的计算资源。
