# 配置

Kestrel Radar 的配置分两处：**启动参数走环境变量**，**日常设置项在界面里改**。第一次使用请看[快速开始](getting-started.md)；各功能的操作路径见[使用手册](usage.md)。

## 启动环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `KESTREL_HOST` | `127.0.0.1` | 监听地址；需从局域网访问可设 `0.0.0.0`，但应用本身没有鉴权 |
| `KESTREL_PORT` | `8765` | 监听端口 |
| `KESTREL_DB_PATH` | `data/kestrel.db` | 数据库文件路径；图标目录位于数据库文件同级的 `icons/` |
| `KESTREL_STATIC_DIR` | 构建产物存在时自动找到 `apps/web/dist` | 前端静态目录；不存在时只提供 API |
| `KESTREL_LOG` | `on` | 默认记录请求日志；设为 `off` 时关闭。除 `off` 外的值目前都会保持开启 |

这些默认值由 `apps/api/src/config/index.ts` 定义。相对数据库路径以**后端进程工作目录**为准，不要假定它永远在仓库根目录；`pnpm start` 会通过包过滤器启动 `apps/api`。Docker Compose 显式配置数据库为 `/data/kestrel.db`，并把 `infra/docker/data/` 挂到 `/data`。

## 界面里的设置

**设置**页有常规、判定、采集、通知、关于几个标签。每张设置卡修改后点“保存”才生效；“重置”只撤销未保存的修改，不会恢复出厂默认。下列默认值来自当前程序；如果你保存过自己的值，以界面中的已保存值为准。界面语言只保存在当前浏览器，其他设置由服务保存。

### 常规

- **界面语言**：切换当前浏览器看到的中文或英文；不会自动翻译已有内容与消息模板。默认中文。
- **时区**：决定界面的时间显示和定时任务按哪个时区理解；默认跟随服务器系统。修改前先确认定时汇总时间在新时区下是否仍符合预期。

### 判定

- **全局判定模式**：默认纯算法，不调用模型；选 LLM+ 后，跟随全局的监听才会按条件调用模型。监听自身也可以明确指定模式，详见[LLM+](llm-plus.md)。
- **宽松、标准、严格三档判分区间**：每档分别设低分线与高分线；到达低分线或更低直接丢弃，达到高分线或更高直接放行，中间是灰区。三档独立保存，并非从标准档自动换算。默认宽松低 25/高 55、标准低 35/高 65、严格低 45/高 80；详细过程与例子见[判定与打分](judgment-scoring.md)。
- **模型调用超时**：单次模型请求最多等多久，默认 30 秒；过时算本次失败，若还可重试或有后续模型会继续尝试。
- **模型失败重试次数**：同一模型首次请求失败后额外重试多少次，默认 1；填 0 则不在同一模型上重试，但仍可能尝试顺序中的下一个模型。
- **模型不可用时**：默认“降级到纯算法”，即原本需要模型复核的内容沿用算法放行结果；另一选项在模型全失败时不给这次判定留下结果，等待以后再尝试，并非把内容判为不通过。请求可能已产生供应商费用，详见[LLM+](llm-plus.md)。
- **全局排除词**：仅在监听选择使用全局排除词时与其自身排除词合并；匹配到的内容直接不通过，不再打分或调模型。默认无。

### 采集

- **并发采集数**：最多同时采集多少个发现，默认 5；调高会增加源站和本机压力。
- **请求超时**：单个发现一次请求最多等待多久，默认 30 秒；超时算本次采集失败。
- **失败重试次数**：采集失败后额外尝试的次数，默认 2；不是采集频率，也不影响模型重试次数。
- **数据保留天数**：超过期限的历史条目和事件由清理流程移除，默认 90 天；缩短前请确认是否还需要旧记录。
- **事件归档时间**：事件持续没有新内容后转为归档状态，默认 14 天；归档与删除历史数据是两件事。
- **内容新鲜窗口**：明确带有过旧发布时间的内容仍可入库，但不再参与投递，默认 7 天；填 0 表示不限制。
- **RSSHub 地址**：当发现填相对路由时，用这里的实例地址访问 RSSHub，默认 `http://localhost:1200`；Docker 里的 localhost 指 Kestrel Radar 容器自己，实例在别处时必须填容器能访问的地址。RSSHub 是独立服务，找路由及验证方法见[使用手册](usage.md#rsshub-是什么怎么找路由)和[官方路由列表](https://docs.rsshub.app/zh/routes/)。
- **访问密钥**：你的 RSSHub 实例需要密钥时才填写；不需要则留空。“测试连接”使用当前输入探测，不会替你保存。

### 通知

- **消息语言**：控制通知中固定文案的语言，例如“有更新”标记和来源的分隔符；不会自动翻译自定义消息模板。默认中文。
- **每日投递上限**：每天最多投递的通知数，默认 0 表示不限；达到上限后内容仍入库，但不会继续投递。
- **投递超时**：单次 Telegram 或 Webhook 投递最多等待多久，默认 15 秒；超时记为投递失败。
- **消息模板**：内置默认模板只有一份正文、不可编辑；可另外创建自定义模板，并在动作中选择。模板变量与实际投递方式见[使用手册](usage.md)。

“关于”页展示版本与仓库信息，没有需要保存的业务设置。输入的允许范围由界面校验，并以服务端规则为准。

## 通知渠道与模型

在**通知渠道**页创建 Telegram 或 Webhook 实例，供分组的动作选择。Telegram 配 Bot token 和会话 ID：可以先让 bot 收到私聊/群消息，再用“读取会话”选择，或者手动填 ID。Webhook 配 HTTP(S) 接收地址与可选密钥；投递为 JSON POST，请求包含渲染后的 `text` 以及事件信息。配置了密钥时，会作为 Bearer 凭据发送。点渠道“测试”**真的会发消息**；这只验证渠道，不验证整条采集/判定链路。密钥保存后不会在读取接口中明文回显；编辑时留空表示保留原密钥。

在**模型**页添加 Ollama 或 OpenAI 兼容供应商，填写接口地址及可选 API Key；模型选项由供应商提供的清单取得，取不到就不会出现在选项中。按调用顺序选最多三个模型并保存，前一个超时/重试失败才尝试下一个。只有确实启用 LLM+ 时才会走模型；模型失败的最终处理由**设置 → 判定**决定；详见[LLM+ 工作细则](llm-plus.md)和[打分规则](judgment-scoring.md)。

## 数据与备份

数据库保存配置、条目、事件、异常与投递记录；图标在数据库文件同级 `icons/`。**备份时要同时覆盖数据库及其 SQLite WAL/SHM 文件，或先停服务再复制整个数据目录**；运行中只 `cp` 一个 `.db` 文件不保证得到一致快照。Docker Compose 的宿主数据目录是 `infra/docker/data/`；脚本/手动运行请先确认实际 `KESTREL_DB_PATH` 与工作目录。

恢复时先停服务，将备份放回对应数据目录，再启动；跨版本回滚前先单独备份数据库，启动时的迁移可能已经改变结构。数据中含渠道密钥与模型 API Key，限制目录和备份副本的访问权限。更多运行方式见[部署](deployment.md)。
