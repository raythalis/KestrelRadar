# Radar V2 UI 与用户提示规格

状态：草案，待 Phase 0 评审冻结

## 1. 主页面

三列：

- Sources：来源与来源组、健康状态、最近成功/失败
- Watchers：监听配置、规则版本、处理模式、运行状态
- Actions：动作模板、目标、调度、成功/失败状态

底部或独立页面提供 Events、Runs、Errors 和容量状态。

## 2. Source 向导

步骤：选择连接器 → 地址与参数 → 认证 → 字段映射（需要时）→ 测试预览 → 保存。

RSSHub 页面应支持实例、路由、参数和测试结果。普通网页/API 支持可视化字段映射；高级模式显示 CSS Selector、XPath 或 JSONPath。

## 3. Watcher 向导

步骤：命名 → 选择多个来源/来源组 → 填写关注描述/目标 → 选择观察类型 → 选择规则或 LLM 辅助 → 设置采集/判断调度 → 绑定多个 Action → 设置失败策略。

## 4. 必须提示的事项

启用 LLM：提示可能产生 Token 费用；Ollama 提示使用本地资源；降级提示说明语义判断会消失。

修改规则：提示只影响未来处理；历史判断和已执行动作不会撤回；历史重评估是显式操作。

来源失效：显示状态、最后成功时间、连续失败次数和受影响 Watcher；提供重新检测、替换、停用、保留等待恢复。

数据保留：展示各类 TTL、数据库上限和超限清理顺序。

动作失败：说明事件已保存，当前动作按重试策略处理，不影响其他动作。

## 5. RSSHub 路由失效展示

状态至少包括 active、degraded、unavailable、invalid、disabled、retired。

页面必须同时展示：

- 路由和实例
- 错误类别（404/不存在、超时、5xx、解析错误等）
- 最后成功时间
- 连续失败次数
- 受影响 Watcher
- 历史数据保留说明
- 可用处置按钮

不自动删除配置或历史数据。
