# 投递说明（M4）

判定通过的命中怎么发出去，这一层说了算。一句话：按动作的触发方式发，同一条内容对一个动作只发一次。

## 触发方式

| 触发方式 | 什么时候发 | 说明 |
|---|---|---|
| 发现即发 | 采集那一轮结束（判定 + 归并做完）就发 | 动作卡片上选「发现即发」 |
| 汇总（每天定时） | 动作上填的时间到点就发 | 把「还没在这个动作上推过的命中」攒成一条 |

两种都走同一个调度器：每个发现、每个汇总动作各注册一个 cron 任务，到点触发（采集层实现在 `apps/api/src/modules/collection/`）。
汇总只决定「多久看一眼」，不是「把这段时间的内容打包」——落到消息里的还是增量。

## 一条内容会不会被推出去

逐条过五道门，任何一道不过就只入库、不通知：

1. **判定留下**：判定层给了「留下」（见 `docs/judgment.md`）。丢掉的、还没判的都不发。
2. **这个动作没发过**：动作 × 内容一张底账，发过的内容不会对同一个动作再发一次。
3. **没过期**：源自己写了发布时间，且早于「新鲜窗口」设置里的天数 → 只入库不推；源没写发布时间 → 不算过期。
4. **没超每日上限**：今天已经发的条数到了上限就先不发，第二天照常。上限 0 表示不限。
5. **事件层没推过**：同一个动作已经推过这件事（事件）→ 默认不再推。只有出现「之前没提过的进展信号」时才补推一次，消息里标「有更新」。

「进展信号」指措辞里明确的新阶段（例如「已确定 / 已上线 / 已停服 / 已修复 / 涨价」这类词）或一个新出现的版本号；
换个人转述同一件事、同一个来源重复转载、标题里原本就有的词，都不算（规则实现在 `apps/api/src/modules/events/`）。

## 合并

- **动作内部合并**（动作卡片开关，默认开）：一次发送里的多条命中合成一条消息；关掉就是一条命中一条消息。
- **渠道小窗口**（3 秒）：同一轮里发往同一个渠道的多个动作合并成一次外发，接收端少被打几次。
- 汇总动作上的**「包含已即时推送过的内容」默认关**：关了就是即时推过的不再进汇总。

## 渠道

v1.0 先支持 **Webhook**；Telegram 需要的 bot token 还没给，接口留好了（`apps/api/src/modules/delivery/sender.ts`）。

**Webhook 协议**：往渠道里填的地址发一个 POST，JSON 体：

```json
{
  "text": "整条消息的正文",
  "title": "事件标题",
  "url": "原文链接",
  "sourceCount": 3,
  "eventCount": 1,
  "hitAt": "2026-10-01T02:00:00.000Z"
}
```

- 渠道配了密钥就带 `Authorization: Bearer <密钥>`，没配就不带。
- 收到 2xx 算成功；其他算失败：记一条 `failed` 的投递记录，内容不标「已投递」，下一轮会重试。
- **连通性测试**按钮是真的发一条测试消息（有副作用，只能手动点）。

## 消息模板（已定）

模板集中在 **设置 → 消息模板** 里管理：

- **系统内置两套（中文 / 英文）**：内容固定在代码里（`apps/api/src/modules/templates/builtin.ts`），界面上只读，不能改也不能删。
- **自定义模板**：有别名（界面上下拉里显示的名字）和正文，可增可改可删。
- **动作只挑模板**：「消息模板」下拉默认「系统内置（跟随界面语言）」，选中后下方只读框展示正文——动作里改不了正文。
- 动作引用的模板被删了 → 渲染时回落到内置模板，不会因此发失败。

占位符写成 `{{名字}}`。认不得的名字原样留在消息里，方便一眼看出写错了哪个。

| 变量 | 含义 |
|---|---|
| `{{title}}` | 事件标题 |
| `{{summary}}` | 摘要（事件里第一条内容的正文片段，超过 120 字截断） |
| `{{url}}` | 原文链接 |
| `{{sourceCount}}` | 来源数量 |
| `{{sources}}` | 来源列表，一行一个（`- 源名：链接`） |
| `{{hitAt}}` | 命中时间，按设置里的时区渲染 |
| `{{group}}` | 分组名 |
| `{{badge}}` | 「有更新」（新事件时是空串） |
| `{{eventCount}}` | 这条消息里装了几个事件 |

默认模板（动作里模板留空时用它；语言跟着设置里的界面语言）：

```
{{badge}}【{{group}}】{{title}}
{{summary}}
来源 {{sourceCount}} 个：
{{sources}}
{{url}}
命中时间：{{hitAt}}
```

```
{{badge}}[{{group}}] {{title}}
{{summary}}
{{sourceCount}} sources:
{{sources}}
{{url}}
Seen at {{hitAt}}
```

一条消息里装多个事件时，事件之间用一行 `---` 隔开（动作内部合并打开时才会出现）。

## 留痕

- `deliveries`：每条外发一条记录（动作、渠道、触发方式、装了哪些事件、成功还是失败、正文、失败原因、时间）。
- `delivered_items`：动作 × 内容的底账，幂等靠它。

两张表只增不改，方便排查「这条为什么没推 / 为什么推了两次」。
