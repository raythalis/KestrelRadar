# 判定与打分规则

Kestrel Radar 采集到新内容后，会用同一分组中已启用的监听判断它是否值得留下。本篇解释“为什么有些内容形成事件，有些没有”；如何创建监听见[使用手册](usage.md)，模型参与时见[LLM+](llm-plus.md)。这里的分数只用于**监听判定**，不是合并相似事件的分数。

## 先看一条内容怎么走

假设监听关键词是“开源”和“模型”，匹配方式选“任意命中”：

1. **先看排除词。**标题或摘要命中任意排除词，直接不通过，不再算分，也不调用模型。监听勾选使用全局排除词时，两处排除词一起生效。
2. **再看包含关键词。**“任意命中”只需找到一个；“全部命中”必须每个都找到。两者都没满足时直接不通过。匹配只检查标题与摘要里的文字，不会猜测近义词或自动理解同义表达。
3. **通过关键词门槛才打分。**命中得越全、出现在标题里，分数通常越高；摘要太短、没有原文链接会扣分。发布时间不参与这个判定分数。
4. **按所选灵敏度的分数线处理。**高分直接通过，低分直接不通过，中间的“灰区”在纯算法模式下保守放行，在 LLM+ 模式下按条件交模型复核。通过的条目才能进入事件归并；没通过或尚未完成判定的不会形成新事件。

如果**没填包含关键词**，规则与上面不同：排除词仍优先；其余内容直接给中性 **50 分**，算法先放行，不因该分数落在低分区而淘汰。LLM+ 只有同时填了意图描述时才会继续让模型判断。一个条目可分别接受同组不同监听的判定，结果不一定相同。

## 分数线怎么理解

每条监听选择“宽松”“标准”或“严格”，对应**独立保存**的一对低分线、高分线。分数**等于低分线也不通过，等于高分线就通过**；两线之间是灰区。默认宽松为低 25 / 高 55，标准为低 35 / 高 65，严格为低 45 / 高 80；你可以在**设置 → 判定**调整。比如标准档得 65 分可直接通过，得 35 分不通过，得 50 分落入灰区。实际以当前已保存设置为准。

有意图描述的 LLM+ 监听还有一个例外：**算法已放行的内容，即便达到高分线，也要交模型判断是否符合意图**。低分或关键词门槛就已不通过的内容不会交模型。纯算法模式不调用模型，灰区会放行。模型请求失败时如何处理见[LLM+](llm-plus.md)。

## 想知道分数怎样算出来

填了关键词并通过门槛时，基础分为 35，再按内容加减：

| 内容情况 | 变化 |
| --- | --- |
| 命中关键词的比例 | 按比例加分，最多加 55，结果四舍五入 |
| 命中词在标题中 | 每个加 5，最多加 15 |
| 两个命中词紧挨出现 | 加 8；最多检查前 10 个命中词 |
| 摘要至少 120 个字符 | 加 8 |
| 摘要少于 20 个字符 | 减 12 |
| 没有原文链接 | 减 4 |

最终分数限制在 0–100。摘要长度按去掉首尾空白后的长度计算；同一个关键词重复出现不会反复加分。比如填“开源”“模型”，两词均命中，其中“开源”在标题，摘要不长也不短、没有相邻词组且有链接：35 + 55 + 5 = **95 分**。默认严格档的高分线是 80，所以算法直接放行；若该监听在 LLM+ 模式下还有意图描述，仍需模型判断。

## 何时会重新判断

正式采集得到还未对该监听判定过的新条目时才处理。首次成功采集建立历史基线；发现卡的“测试采集”只探测来源、不写入条目。修改监听规则**不会自动重判已有判定的历史内容**。当前界面没有可用的监听规则预览入口；后端虽有只读试算接口，但它不调用模型、也不保存最终判定，不能当作一次正式采集。
