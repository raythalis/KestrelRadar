# 判定流程说明（M3）

判定回答一个问题：**这条内容该不该留下**。四层漏斗，每一层都能被用户看懂。

## 一、四层漏斗

| 层 | 做什么 | 拦下来的样子 |
| --- | --- | --- |
| 1. 来源范围 | 只判「这个分组里启用的发现」采到的内容；分组或监听停用就不判 | 不进漏斗（没有判定记录） |
| 2. 关键词门槛 | 填了就作门槛；不填=全部通过。匹配方式 **任意命中 / 全部命中** 可选 | `layer: keywords`，理由写清缺哪个词 |
| 2b. 排除词 | 单独一层，命中直接丢；可勾「追加全局排除词」 | `layer: excludes`，理由写清是哪个词 |
| 3. 打分 | 算 0–100 分，分三档：高分放行 / 低分丢掉 / 灰区 | `layer: score`，理由写清几分、落哪档 |
| 4. 模型（仅灰区或写了意图描述） | 回「是 / 否 + 一句理由」，判否就丢 | `layer: llm`，理由记在 `llmReason` |

判定**在条目层**做（每条内容各自过），投递在事件层（M4）。同一轮里一条内容对一条监听最多判一次，靠数据库唯一约束（`item_id + monitor_id`）兜住。

## 二、打分信号（全部可解释，权重写死在代码里）

底层 35 分起步；**没填关键词**时给中性分 50（落在灰区，纯算法模式放行）。

| 信号 | 加减分 |
| --- | --- |
| 关键词覆盖（命中数 / 关键词总数） | 最多 +55（全覆盖） |
| 标题命中 | 每个 +5，最多 +15 |
| 多个命中词在正文里连在一起出现（例如「开源模型」） | +8 |
| 正文 ≥ 120 字 | +8 |
| 正文 < 20 字（信息量有限） | −12 |
| 没有链接（回不到原文） | −4 |

分数最后夹在 0–100。**发布时间不参与判定**（它只影响排序）：抓取间隔长的源不会被误杀。

来源权重在 v1.0 没有配置入口，所有来源等权；这个信号位保留着，等真有需要再加。

## 三、两条线与灵敏度

高级设置里两条线（默认 **高 65 / 低 35**）就是**标准**灵敏度的分界；监听卡片上的灵敏度只是把它们整体平移：

- 宽松：两条线各 −`sensitivityShift`（默认 10）→ 55 / 25
- 标准：65 / 35
- 严格：两条线各 +10 → 75 / 45

灰区在两个模式下的处理不同：**纯算法模式灰区默认放行**（保守偏向不漏）；**算法 + LLM 模式**灰区交模型复核。被关键词门槛或低分丢掉的内容**不会**再叫模型（省钱的顺序）。

## 四、模型接口与降级

`JudgeLlm` 只有 `review()` 一个方法，输入意图描述 + 标题 + 正文，输出「是 / 否 + 理由」。M3 只留接口，没有接任何供应商：真被调用时抛「还没有配置可用的判定模型」。

模型不通时按高级设置里的降级开关走：

- `fallback`（默认）：回到纯算法结果放行，理由里写明「模型不通，已降级为纯算法处理」
- `error`：这条这次不落判定（等下次再判），只写一条告警日志；**不会**因为模型挂了就把内容当没命中丢掉

## 五、规则预览

`POST /api/monitors/:id/preview`：拿这个分组**最近采集到的内容**试跑。

- 可以带一份**临时规则**（不保存），方便在界面里改一个字段就看结果
- 只做算法判分，**不调模型**；灰区会不会走模型用 `needsModel` 告诉界面
- **不写任何判定记录**，也不改监听本身
- 返回：总数、命中数、丢掉数，外加最多 3 条样例（标题 + 命中词 + 理由）

## 六、判定结果落在哪里

每条约的内容 × 每条监听 = 一条 `judgments` 记录：`decision`（pass/drop）、`band`（high/gray/low）、`score`、`matchedKeywords`、`layer`、`reasons`（人话，多条）、`llmReason`。

没命中的内容**照样存在 `items` 里**，判定记录里是 `drop`；仪表盘默认隐藏、可以查，并能一键把某个词加进关键词（M5/M6 做）。

## 七、v1.0 已知边界

- 判定只在**采集到新条目之后**做（每个发现一个 cron 任务，采完顺手判）；库里已有的旧条目不会自动补判，要用监听卡片的「试跑」看
- 监听规则改了**不会**重判历史内容（避免改一次词就把整库重算一遍）
- 预览不调模型（省钱）；真正走模型的是采集时的灰区复核与意图判断
