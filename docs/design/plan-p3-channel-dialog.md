# ChannelDialog 通知渠道弹窗（/design 原型，第一版）

状态：**已出原型**，等他批注。四张卡片（Channel/Source/Action/Monitor）已冻结，这轮只做弹窗内容。

## 字段（按「这个渠道怎么发出去」排）

| 顺序 | 字段 | 说明 |
| --- | --- | --- |
| 1 | 启用 | 开关，跟卡片那个是同一个值 |
| 2 | 名称 | 必填，最长 60 |
| 3 | Bot token | 仅 Telegram；必填（除非已经存过密钥） |
| 4 | 会话（chat id） | 仅 Telegram；必填，旁边是「读取会话」 |
| 5 | Webhook 地址 | 仅 Webhook；必填，等宽显示 |
| 6 | 密钥（可留空） | 仅 Webhook；放进 `Authorization: Bearer ***` |

**类型不作为字段**（2026-10-02 他定的）：弹窗固定只管一种渠道，类型由调用方传进来；
「加渠道时先选类型」这件事放在通知渠道页那一步做（P3），弹窗里不再出现类型选择。
种类通过标题表达——「编辑 Telegram 渠道」「新建 Webhook 渠道」。

底部只有「取消 / 保存」，保存按钮在表单没填全时不可点（不用文字解释为什么不可点）。

## 密钥的处理（接口决定的）

接口只回「配过没有」（`hasSecret`），**从不回显密钥本身**。所以：

- 配过：输入框留空，占位文字是「已保存过，留空表示不改」；输入即覆盖。
- 没配过：占位与提示引导去 BotFather 拿 token（这条是用户从界面推不出来的信息，留着）。
- 提交时只带当前类型的那一个密钥字段：Telegram 带 bot token，Webhook 带签名密钥。

## 「读取会话」

点一下把 bot token 交给 Telegram `getUpdates`，读出 bot 见过的会话，点一条就填进 chat id。
读不到时提示「先把 bot 拉进群、或在私聊里给它发一句话」。
演示页里是假数据（800ms 后返回两个会话）；真接口在 P3 接。

## 从 MP 借了什么、没借什么

借：字段顺序（启用 → 名称 → 类型 → 凭证 → 目标）、密钥单独一栏、读取会话的思路。

**没借（Kestrel 用不上）**：

- 用户白名单 / 管理员白名单 —— MP 的 bot 会接命令，要限制谁能用；Kestrel 只单向推送，没有命令入口。
- 代理 API 地址 —— 后端把 `https://api.telegram.org` 写死了（`delivery/telegram.ts`），加字段得先加后端支持；当前 NAS 能直连，先不加。

## 他已经拍板的

- 「启用」留在弹窗里（渠道卡上没有开关，只有连通圆点）。
- 弹窗里不要「发送测试」按钮。
- 密钥不给「清空」入口（只在编辑时覆盖）。
- 类型不进弹窗，固定一种渠道；选类型放在添加时，属于通知渠道页那一步。

## 待他定夺

1. 要不要 MP 那种两列布局（这里字段少，现在是一列；弹窗宽 480）。
2. 字段多起来之后桌面弹窗内容区要不要改成可滚动（现在只有手机端那层会滚）。
