## 一、现状（实测证据）

### 外壳由三个部分拼成

| 部分 | 现状 |
| --- | --- |
| `AppSidebar` | 左栏 224px：品牌行 48px（logo 28 + 名字 14px + 版本号）→ 导航 → 版本脚注；窄屏变成抽屉（`translateX(-100%)` 藏在屏幕外，遮罩点击关闭），并且**同一份导航**在底部再渲染一遍（`app-tabbar`） |
| `AppHeader` | 顶栏 48px，粘性：窄屏有抽屉按钮 + 当前页名，右侧是语言按钮与亮暗三态；**桌面把抽屉按钮和页名都隐藏**（`display:none`），只留右侧操作 |
| `AppPage` | 页面容器：标题 + 一句说明 + 右侧操作 + 内容；宽度档 narrow 720 / default 1120 / wide 1440 / full 不限 |

### 发现的问题（都属于"框架层"，不是某一页的问题）

1. **页面骨架是空的**：`AppPage`/`AppSection` 已经做好，但**五个产品页一个都没用**（只有 `/design` 用了 7 处）。
   正式页面各自写老样式的 `page-head` 结构，跟外壳不是一套。
2. **手机端标题重复**：390 下顶栏显示「配置管理」，页面自己又渲染一个「配置管理」大标题（桌面因为顶栏隐藏页名反而不重复）。
3. **文档标题不随页面变**：浏览器标签永远是 `Kestrel`（`index.html` 里写死），没有任何按路由设置标题的代码。
   （附带说明：本次实测时旧标签上曾显示过一个带 emoji 的标题，但刷新后即回到 `Kestrel`，
   当前代码里搜不到任何设置标题的地方，也不是本仓库历史里的东西 —— 属历史标签残留，不是现状缺陷。）
4. **导航写死在外壳里**：五项在 `AppShell.vue` 的常量里，业务页与设置页平铺，没有分区。
5. **没有 404**：未知路径直接 `redirect` 到仪表盘。
6. **页面级三态没有固定位置**：`AppSkeleton`（骨架）、`AppEmptyState`（空态）都有，但"加载/空/出错"放哪、要不要挡住页面头，
   没有统一约定，各页自己摆。

## 二、要定的东西

1. **标题归属**（见下方案 A/B）—— 一页的标题到底由顶栏显示还是由页面显示，二者只留一个。
2. **页面骨架契约**：正式页面一律 `AppPage`（标题 + 一句说明 + 宽度档 + 操作）+ `AppSection` 分节；
   老 `page-head` 结构在 P2/P3 逐页替换。
3. **页面级三态**：加载 / 空 / 错误的固定位置（建议在 `AppPage` 里留位：三态替换内容区，页面头保留）。
4. **导航分区**：业务（配置 / 渠道 / 模型）与设置分开，或保持平铺。
5. **文档标题**：按路由设置，形如「配置管理 · Kestrel」。
6. **404**：加一页，或维持现在的重定向。

## 三、标题归属：两案

| | 案 A（我建议） | 案 B |
| --- | --- | --- |
| 做法 | **顶栏不再显示页名**（桌面手机一致），页名一律由页面的 `AppPage` 标题承担 | 顶栏显示页名（现在的手机行为），页面不再写大标题 |
| 好处 | 一页自然拥有「标题 + 说明 + 操作」这一层；手机少一行；滚动时标题仍可见（它是页面内容的一部分） | 滚动到深处时顶栏始终告诉你在哪 |
| 代价 | 滚到深处时顶栏没有位置提示 | 页面无法承载标题与说明（`AppPage` 的 API 变成摆设），且顶栏要挤页名与操作，手机更紧 |
| 现状相容 | 安全：五个旧页面自己都有 `page-head` 标题，去掉顶栏页名不会出现"没标题"的页面 | 需要逐页删掉自带标题，否则重复（P2/P3 才做） |

两案都可以再加一条：**窄屏顶栏放一个小的品牌标**（现在只有抽屉按钮 + 页名），让手机上也能一眼认出是哪个应用。

## 四、影响范围与回滚

- 代码：`layouts/AppShell.vue`、`components/app/{AppHeader,AppPage,AppSidebar}.vue`、`styles/components.scss`、路由（文档标题/404）。
  **不动**业务组件与业务页面。
- 影响面：外壳是全局的，改完五个页面都跟着变 → 逐页在 1440/390 走一遍确认没有破版。
- 回滚：集中在少数文件，单 commit 可回滚；文档标题与 404 各自独立、可单独去掉。
