# MonitorDialog 监听弹窗（/design 原型，第一版）

状态：**已出原型**，等他批注。四张卡片已冻结，这轮做监听弹窗。

## 字段（按「这条监听什么时候算命中、命中之后怎么走」排）

| 顺序 | 字段 | 说明 |
| --- | --- | --- |
| 1 | 启用 | 开关 |
| 2 | 名称 | 必填，最长 60 |
| 3 | 模式 | 跟随全局 / 自带算法 / 算法 + LLM |
| 4 | 意图描述 | **只在「算法 + LLM」时出现**；最长 500，多行 |
| 5 | 关键词 | 标签输入，回车/逗号加一个，可单个删；提示只留「留空＝全部通过」 |
| 6 | 匹配方式 | 任意命中 / 全部命中 |
| 7 | 排除词 | 标签输入 |
| 8 | 追加全局排除词 | 开关 |
| 9 | 灵敏度 | 宽松 / 标准 / 严格 |
| 10 | 只走这几个动作 | 多选，选中项显示成标签；提示「留空＝跟随分组」 |

按钮只有取消 / 保存，没填名称时保存不可点；底部没有「发送测试」这类额外入口。

## 版式：桌面两列，窄屏一列

成对的短字段并排、长字段跨满两列：

| 行 | 内容 |
| --- | --- |
| 1 | 启用（整行） |
| 2 | 名称 ｜ 模式 |
| 3 | 意图描述（整行，仅「算法 + LLM」） |
| 4 | 关键词（整行） |
| 5 | 匹配方式 ｜ 灵敏度 |
| 6 | 排除词（整行） |
| 7 | 追加全局排除词（整行） |
| 8 | 只走这几个动作（整行） |

900px 是分界：往上两列，往下自动回到一列。弹窗宽度跟着从 560 放到 640，两列才排得开。
代价是「灵敏度」比原顺序往前提了一格（挪到「匹配方式」旁边成对），其余顺序没动。

## 卡脚（2026-10-02 二次定版）

原来写「灵敏度 严格」这种「字段名 + 值」的元信息，现在只留一个**方角 AppStatus 写档位**（宽松 / 标准 / 严格），
不写「灵敏度」三个字、不带圆点；**排除词数量从卡脚去掉**（`excludeCount` prop 与 `monitor.excludeCount` 文案一并删掉）。
AppStatus 为此加了 `square`（方角）一档。

## 这一版做的取舍

- **意图描述跟着模式出现/消失**：它只在「算法 + LLM」下生效，于是别的模式直接不占地方（值留在表单里，切回来还在）。
  老弹窗那种「跟随全局时告诉你为什么看不到意图描述」的说明文字去掉了——字段在不在这件事本身已经说清楚了。
- **关键词与排除词用标签输入**：配套新增 DS 组件 `AppTagsInput`（内部是 Vuetify 的 v-combobox，
  回车/中英文逗号/分号/空格都分段，粘一串也会拆开，重复与空串自动丢）。
- **意图描述用多行**：配套新增 DS 组件 `AppTextarea`（跟 AppInput 同一套状态与留白）。
- **「只走这几个动作」是多选**：`AppSelect` 加了 `multiple` 能力（选中项显示成可删标签）。

## 顺带修掉的一个真问题：字段多了以后弹窗按钮点不到

实测 1032×685 的窗口里，这个 10 字段的弹窗把「取消 / 保存」顶到了视口外面，鼠标够不到按钮。
原因是 `.app-dialog` 虽然有 `max-height`，但内容那层没有 `min-height: 0` + `overflow-y: auto`，
flex 子项不肯缩，内容就整个溢出弹窗盒子。

修法（在 `styles/components.scss`，所有弹窗一起受益）：头尾留在原位，中间那层自己滚。
修完实测：弹窗高 653 < 视口 685、内容 842 在内部滚动、脚底 676 在视口内；390 宽的手机上同样成立。

## 演示页怎么验

`/design` → 业务组件 → 监测组：

- 点监听卡＝编辑（预填全部字段），下面「添加监听」＝新建。
- 第二张卡是「算法 + LLM」，能直接看到意图描述那一栏；把模式切到别的，那一栏会消失。
- 关键词/排除词可以真打字回车加标签、点标签上的 × 删掉；保存后卡片会跟着变。

## 待他定夺

1. 「算法 + LLM」下意图描述要不要必填（现在不填也能存）。
2. 关键词与排除词现在都放在弹窗里纵向排；要不要合成一行（关键词 + 匹配方式并排）。
3. 「只走这几个动作」这个叫法认不认（后端字段是 `actionIds`，空＝跟随分组）。
