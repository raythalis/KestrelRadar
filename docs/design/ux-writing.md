# Kestrel · UX Writing / Content Design 规则

状态：**生效**（2026-10-02 定）。后续所有页面（P2 起）按这份规则写文案。
审查结论见文末「现有文案审查（只读）」。

## 一、核心原则

**界面应该自解释，而不是解释界面。**

判断标准只有一条：**删掉这句话，用户会不会做错？**
会 → 放到对的位置（字段 hint / tooltip / 空状态 / 危险操作确认 / 报错）；不会 → 删掉。

目标不是「少写字」，而是让用户通过界面本身理解产品，而不是让产品不断解释自己。

## 二、允许出现的文字（只有这四类）

| 类别 | 例子 | 位置 |
| --- | --- | --- |
| 标签 / 字段名 | 「通知渠道」「Bot Token」 | 字段自身 |
| 状态（短名词短语） | 「未选择通知渠道」「连通」「已停用」 | 状态位、卡片状态行 |
| 报错（一句话，说清哪里不对） | 「表达式要五段（分 时 日 月 周）」 | 字段下方 |
| 危险操作的影响范围 | 「还在用它的动作会发不出去」 | 删除确认里 |

## 三、禁止出现的文字

1. 教用户点哪里：「改完点这张卡的『保存』」「再点一次」。
2. 实现细节：「程序自己拼」「只会读，不会改库里的数据」「放在请求头 Authorization: Bearer」。
3. 为凑版面写的 description：卡片说明、页面副标题里对功能的泛泛介绍。
4. 同一信息的第二次表达：字段名已说明的，不再写一段解释；状态已有视觉的，不再写句子。
5. 版本/进度说明：「v1.0 只登记…」「仪表盘先占位…」。

## 四、写法约束

- 长度：状态 ≤ 8 字；字段 hint 一行（约 24 字）；报错 ≤ 一句；删除确认 ≤ 两行。
- 语气：中性、专业、现在时；不用「您」，不用感叹号，不卖萌，不写教程口吻。
- 术语：只在用户必须自己输入/判断时出现，并且出现即解释一句（例如「群是负数、私聊是正数」）。
- 示例值：只在没有它用户真的写不出来时给（例如「杨幂的新电影」这种自然语言输入示例）。
- 表述对象：写「用户要做什么」，不写「系统内部怎么工作」。

## 五、豁免

- `/design`（Design System 预览页）是开发/验收用的，不受本规则约束——它的说明文字是给实现者看的。
- 报错、空状态、删除确认里的事实性说明保留，但按上面的长度与语气收紧。

### D. 重复解释

- 时间类字段：cron 生成器 + 人话翻译 + 例子三处表达同一件事 → 只留生成器（已按此改 CronPicker）。
- 「分组是什么」在 `config.subtitle` 与 `config.empty` 各解释一次。
- 「模板只读」在 `/design` 演示与 `template.sectionNote` 各写一次 → 只留字段的只读态。

### E. 可以交给 UI 状态的（不再写句子）

渠道连通 / 试抓结果 / 来源条数 / 基线 / 未选渠道 / 停用 → 状态标签 + 颜色 + 图标。

### F. 保留（真正需要，只做收紧）

- 删除确认里的影响范围（5 处 `*deleteBody`）：保留，去掉「本身」这类赘词。
- `settings.range`「可填 {min} – {max}」、`model.apiKeyHint`「本地 Ollama 一般不用填」：字段约束与默认值，UI 表达不了，保留。
- `config.groupSummary`「{d} 发现 · {m} 监听 · {a} 动作」：数据摘要，保留。

## 七、处理顺序（待确认后逐页执行）

1. P2 Dashboard 开始前：先按本规则清掉 `placeholder.dashboard` 与导航相关文案。
2. P3 配置页（设置 / 渠道 / 模型）：改文案随页面改造一起做，不单独回来改。
3. P5 其余页面：逐页过一遍 A–E 类。
4. 每页完成时自查四个问题：有没有教点击、有没有实现细节、有没有第二遍解释、能不能换成状态。
