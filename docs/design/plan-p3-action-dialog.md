# ActionDialog 动作弹窗（/design 原型，第一版）

状态：**已出原型**，等他批注。监听弹窗已冻结，这轮做动作弹窗。

## 字段（按「这条动作什么时候发、发到哪、发成什么样」排）

| 顺序 | 字段 | 说明 |
| --- | --- | --- |
| 1 | 启用 | 开关（整行） |
| 2 | 名称 | 必填，最长 60 |
| 3 | 触发方式 | 发现即发 / 每天汇总 |
| 4 | 汇总时间 | **只在「每天汇总」时出现**；cron 字段，点开就是生成器。表达式不合规时保存不可点 |
| 5 | 通知渠道 | **必填**，候选由页面传进来（真页面拿渠道列表） |
| 6 | 消息模板 | 第一项是「系统内置（默认模板）」；选它交出去的是 `null` |
| 7 | 合并为一条消息 | 开关 |
| 8 | 包含已即时推送过的内容 | 开关，**只在「每天汇总」时出现** |

桌面两列（跟监听弹窗同一套排法）：开关与汇总时间跨满两列，名称 + 触发方式、渠道 + 消息模板、两个开关各自成对；
900px 往下回到一列。弹窗宽度 640。

## 通知渠道下拉（2026-10-02 二次定版）

下拉每一项：**左边一个图标标出渠道类型**（telegram → `mdi-send`、webhook → `mdi-webhook`，取自 `components/biz/icons.ts`），
**右边用 AppStatus 标出还没启用的渠道**（红点 + 「未启用」）。停用的渠道仍然可选——卡上会给它挂红 tag，
这里只是先把话说在前面。

渠道候选因此带上 `type` 与 `enabled` 两个字段：页面传来的 `channels` 形状是 `{ id, name, type, enabled }[]`。
字段本身（收起时）还是纯文字写渠道名，没加图标。

## 超长渠道名实测（2026-10-02）

把演示里的 `demo.channel.mine` 临时换成一个 43 字的渠道名，实测三处：

| 位置 | 结果 |
| --- | --- |
| 字段收起时 | 正常：`.v-select__selection-text` 自己出省略号（233 宽 / 内容 694 宽），不挤到图标 |
| 下拉菜单 | **坏了**：Vuetify 按最长那一项把菜单撑宽，640 的弹窗被撑到 **792**，手机上会直接溢出屏幕 |
| 下拉项里的「未启用」 | 被推到菜单外沿（右边缘 982 > 菜单 829） |

修法（`components/app/AppSelect.vue`，所有下拉一起受益）：给 v-select 挂 `menu-props` 的 `maxWidth`，
上限 = `min(640px, 100vw - 2 * --k-space-4)`。菜单最宽跟弹窗齐平，超出的文字自己出省略号。

修完实测：

- 桌面 1032：菜单 640（不再外扩），长名字标题 558 / 内容 710 → 出省略号；「未启用」仍在菜单内（右 830）
- 手机 390：菜单 364（13 → 377，留在屏内），标题 282 / 内容 710 → 出省略号；「未启用」右 361
- 换回正常名字：菜单 295，图标与「未启用」都照旧

演示里的临时超长名已还原。

## 这一版做的取舍

- **名称和通知渠道都必填**：后端 `createActionInputSchema` 里 `channelId` 没有默认值，没渠道的动作本来就发不出去——
  入口这里先挡住，别让人存下一张注定发不出去的动作。列表为空时这个字段是空的、保存点不动。
- **汇总时间只在汇总时占地方**：`cron` 后端允许为 null，发现即发交出去的就是 `null`。
- **模板第一项是系统内置**：对应后端 `templateId: null`，弹窗内部用空串占位，交出去再换回 null。
- **没有放模板正文预览**：老弹窗有一块「当前模板内容（只读）」，但模板本身还没设计（正文语言也还悬着），
  这轮先只给选择框。
- **没放汇总时间的人话提示**：老弹窗那句「每天几点汇总，例如 0 9 * * * 是每天 09:00」去掉了——
  字段点开就是生成器，时间的含义由生成器表达。
- **`mergeMessages` 文案缩短**成「合并为一条消息」（英文 Merge into one message）。老弹窗那句长解释念着费劲，
  开关下面也不需要解释。

## 顺带修的：卡片网格与操作行之间没有气口

`.app-card__body` 只有 padding、没有 gap，所以「添加动作 / 添加监听」这排按钮紧贴着上面的卡片网格（间距 0）。
在 `styles/components.scss` 加了一条相邻规则：`.app-card-grid + .app-row { margin-top: var(--k-space-3) }`，
实测间距 0 → 12px（监听组与动作组都验过）。

## 演示页怎么验

`/design` → 业务组件 → 动作组：

- 点动作卡＝编辑（预填全部字段），下面「添加动作」＝新建。
- 第二张卡是「每天汇总」，能直接看到汇总时间与「包含已即时推送过的内容」；切到「发现即发」两栏会消失。
- 卡上的渠道名与模板名由演示数据里的 id 现算（不再各存一份文案），改渠道名会跟着变。

## 待他定夺

1. 没渠道的时候要不要在弹窗里放一个「新建渠道」入口（老弹窗有 `channelAdd`，这轮先没搬）。
2. 消息模板要不要在弹窗里给一块只读的正文预览（等模板本体定下来再说）。
3. 「只走这几个动作」在监听弹窗里引用动作名；动作改名后引用会自动跟着变，这个行为认不认。
