# Kestrel · 正式页面设计规则（Design Lab 不是产品）

状态：**生效**（2026-10-02 定）。P2 起按这份规则设计页面。

## 一、核心区分

| | `/design`（Design Lab） | 正式页面（P2 起） |
| --- | --- | --- |
| 目的 | 展示组件能力与状态 | 解决用户任务 |
| 组织方式 | 按组件分组 | 按用户任务与信息层级 |
| 状态 | 尽量铺开 | 只带真实存在的状态 |

**Design Lab 是展示组件能力的地方，正式产品是解决用户任务的地方。不要反过来。**

## 二、禁止照搬

- 不要把 `/design` 的组件展示结构当成正式产品的信息架构。
- 不要为了展示组件能力，把所有状态都带进正式页面。
- 不要把 `/design` 的状态说明文字（"状态：连通 / 未测 / 有警告…"）带进正式页面。
- 不要把开发者视角的状态与实现细节直接暴露给用户。

## 三、逐条红线

1. **不要所有卡片都塞满元数据。** 卡片只带用户此刻要判断的东西，其余进详情。
2. **同一个状态只表达一次。** 左边框、彩色图标、状态圆点、状态文字不要同时上；选一种，最多两种（颜色 + 短标签）。
3. **操作分层级。** 主要操作、普通操作、危险操作不能同一视觉层级；危险操作不进主视线。
4. **结构服从任务。** 管理场景优先考虑列表、表单、详情抽屉，而不是卡片墙。
5. **卡片不是默认答案。** 先问「这里用户要完成什么」，再决定用列表、表单还是卡片。

## 四、每个页面开工前的自查

- 这个页面的用户任务是什么？一句话写出来。
- 信息层级是什么：一眼要看什么、看一眼之后才看什么、什么时候才需要展开？
- 每一块数据是不是此刻就要显示？能不能进详情抽屉？
- 每个状态是不是真的会出现？假状态一律不带。
- 三个操作是不是分了层级？
- 有没有把 Lab 里的说明文字抄过来？有就删。

## 五、与 UX Writing 规则的关系

文案规则见 `docs/design/ux-writing.md`（界面自解释；需求文档是唯一语义来源）。
两份规则一起用：**结构先按用户任务定，文案只写标签、状态、报错、影响范围。**
