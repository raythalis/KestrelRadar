# MonitorCard 监听卡片（/design 原型，第一版）

状态：**已在 /design 出原型**，等他批注。ChannelCard / SourceCard / ActionCard 这轮没动。

## 结构：跟数据源卡、动作卡同一骨架
| 位置 | 放什么 | 为什么 |
| --- | --- | --- |
| 卡头 | 图标 + 监听名 + 判定模式（跟随全局 / 自带算法 / 算法 + LLM） | 判定的方式决定后面看什么 |
| 右上角 | × ＝删除（二级确认由页面做） | 三张卡统一：危险操作收在角落 |
| 正文 | 关键词标签（最多 3 个，多的给 +N）+ 匹配方式（任意/全部命中） | 卡上回答「这条监听留下什么」 |
| 正文 | 没填关键词就写「没填关键词（全部通过）」 | 状态自己说，不写解释段落 |
| 正文 | 意图描述（只有「算法 + LLM」有） | 一句话，不是标签 |
| 卡脚 | 灵敏度、排除词数量、右下角开关 | 附属信息不占正文 |

- **没有左侧色条**（`biz-card--no-bar`）——跟数据源卡/动作卡一致；监听没有像渠道卡那样的「连通状态」需要竖条表达。
- 点整张卡＝编辑，卡上不摆编辑按钮；不写「被 N 个动作使用」这类填充信息。
- 关键词标签用 `AppTag`（App* 层），不用裸 span。
- 硬边界：组件只出事件（edit / toggle / delete），数据、写操作、删除确认都由页面负责。

## 待他定夺
1. 灵敏度放卡脚够不够（他说保留，位置待看效果）。
