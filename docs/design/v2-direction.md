## 一、为什么是整套重做

用户已明确要参考图那种**消费级产品**的观感。消费级的感觉不在 v1 的刻度里：
v1 是字号 13 起、间距最小步进 4、圆角 3–6px、卡片不带阴影只靠描边、按钮 32 高、颜色是偏深的工具色。
这些值互相咬合，单独放大一两样只会显得别扭，所以另起一套完整 token，而不是继续打补丁。

## 三、组件规则（消费级，但不失信息）

1. **卡片**：圆角 20、内边距 24、静置 sm 阴影、悬停抬 4px 并加深阴影；卡片顶部一道极淡的品牌色晕（`--k2-grad-wash`）是消费级观感的主要来源。
2. **语义色三件套**：实色只用于图表条形与品牌渐变；图标与芯片一律用「柔和底 + 深色文字版」，小字号也能看清。
3. **图标容器**：44px、圆角 12、柔和语义底，接管原来"左侧色条"的职责；列表行里用 32px 小号。
4. **数值**：关键数字走等宽字、32px / 700，单位降到 12px；下面一条品牌渐变短条做强调。
5. **一行一卡一主操作**：实心按钮最多一个，其余走描边按钮或文字链。
6. **密度与原版的取舍**：字号与留白整体放大，同屏卡片数会少于 v1，这是选消费级的必然代价；列表行仍保持 52px 的可扫读密度。
7. **状态一套齐**：键盘焦点环（3px、品牌色透明版）在按钮 / 链接 / 输入框 / 可点卡片上共用；禁用态用专门的底色与字色，不靠整体降透明度；加载用骨架（底色 + 一道扫光）；进度与占比用轨道 + 语义色填充。
8. **关联高亮**：桌面端点一项，同组的其他项一起亮——底色 + 一圈描边，不改变文字色，因此不牺牲可读性。

## 四、可读性实测

亮暗各 9 组关键配对全部达到 WCAG AA 4.5:1：

| 配对 | 亮色 | 暗色 |
| --- | --- | --- |
| 正文 / 卡片底 | 17.9 | 16.1 |
| 次要文字 / 卡片底 | 6.2 | 8.1 |
| 最弱文字 / 卡片底 | 4.76 | 4.71 |
| 按钮文字 / 品牌色 | 4.88 | 4.88 |
| 品牌色文字 / 品牌柔和底 | 6.93 | 7.53 |
| success / warning / danger / info 文字版 / 各自柔和底 | 5.07 / 4.82 / 5.62 / 5.26 | 10.2 / 8.4 / 7.3 / 9.5 |

| 关联高亮底上的正文 | 15.3 | 12.3 |

（语义实色压在白底上对比度只有 2.3–3.9，所以规则里明确：实色不做文字，只做图形与渐变。
禁用态的两组（2.0 / 4.0）按无障碍豁免处理：禁用元素不要求对比度，但色值专门挑过，
比正文弱、又不会糊成一团——守卫测试把它登记为下限，不当作通过项。）

## 五、边界与验证

- **独立**：v2 不引用任何 `--k-*` 变量，颜色/字号/间距全部自己定义；现有 token、样式、页面一行未改。
- **隔离**：`--k2-*` 只写在预览容器上。实测进入预览页前后 `<html>` 的 `--k-radius-md` 仍是 4px、主题未变；预览页切亮暗只改容器。
- **无死变量**：实际执行 `v2Vars()` 得到 114 个变量，与实际引用双向对齐——没有发出却不用的，也没有用了却没定义的。
  这条现在由守卫测试自动盯着（`src/__tests__/design-v2.spec.ts`）：字面量扫一遍，拼出来的名字按前缀认领；
  同时校亮暗两套键一致、色值合法、正文/次要/最弱文字与关联高亮底上的正文都过 AA 4.5。
- **刻意不加的**：z-index 阶梯与断点值——CSS 变量进不了媒体查询、目前也没有消费方，加了就是死变量；
  它们等外壳与弹窗真正落地时随组件一起进。
- **图标**：预览页用到的 20 个图标都在现有 MDI 子集内（没有新增图标字体）。
- **切换不被动画拖住**：换主题时先关过渡、强制重排再打开（`.k2-instant`）。
- **类型检查与守卫单测**：`vue-tsc --build` 通过；前端 **44 文件 / 288 用例**全过（含 `design-v2` 5 条、`style-lab` 11 条），`oxlint` 0 警告 0 错误。
- **真机实测**（`http://192.168.5.100:5173/style-lab`）：11 个 section、9 张翻卡、8 张指标卡、3 列 + 3 个新增位、2 条分线手柄、14 个开关、空态与骨架各 1 组；分线拖动 35 → 50 生效；预览容器外 `--k2-*` 数量 0。

## 七、落地路径

方向确认后，在**主题阶段**把 v2 的值并入 `design/tokens`（**替换** v1 里对应的形状/颜色/排版值，而不是两套并存），
再把 `styles/v2.scss` 的规则搬进 `components.scss` / `biz.scss`，最后删掉预览页与 v2 层——v2 的产出物是"改 v1 的那批值"，不是长期第二套 token。
