# 快速开始

这篇带你从零启动 Kestrel Radar，并建立第一组能采集、判定和投递的配置。各种安装方式的完整命令、数据目录与升级方法见[部署](deployment.md)。

## 1. 启动并打开界面

先取得项目源码。Linux/macOS 运行 `./start.sh`，Windows 可运行 `start.bat`；脚本需要预先安装 Node.js 和 pnpm，并会在当前终端构建和启动服务（不是后台服务）。详细条件及 Docker 安装方式见[部署](deployment.md)。

```bash
./start.sh
```

然后在同一台设备上打开 <http://127.0.0.1:8765>。若需从局域网其他设备访问，启动前设置 `KESTREL_HOST=0.0.0.0`，并用运行主机的局域网地址打开；Docker 的端口映射与限制访问的方法见[部署](deployment.md)。**Kestrel Radar 当前没有账号与鉴权，不要直接暴露到公网。**

首次启动会建立数据库。Docker 数据保存在 `infra/docker/data/`；脚本/手动启动的相对数据路径取决于后端进程工作目录。备份前先按[配置](configuration.md)确认实际路径。

## 2. 准备一个发现

如果使用 RSSHub 路由，先在**设置 → 采集**中核对 RSSHub 基础地址；默认是运行 Kestrel Radar 的环境内的 `http://localhost:1200`。在 Docker 中它指容器自身，RSSHub 跑在另一容器或主机时必须改成 Kestrel Radar 能访问的地址，并可用页面上的测试入口检查。路由从 [RSSHub 官方路由列表](https://docs.rsshub.app/zh/routes/) 查找并按说明填好参数；概念、路径写法和验证步骤见[使用手册的 RSSHub 小节](usage.md#rsshub-是什么怎么找路由)。直接使用 RSS/Atom 订阅地址则不需要 RSSHub。

打开**配置管理**，新建一个分组，再在分组的**发现**列添加发现。选 RSS 源并填完整 `http://` 或 `https://` 订阅地址，或选 RSSHub 路由并填路由、选网页地址让程序寻找其 RSS/Atom 链接；填写名称与采集频率并保存。采集频率可点输入框用生成器选择，也可直接输入五段表达式。**目前保存前不会自动测试采集**；保存后用发现卡上的“测试采集”验证连通性。手动测试不写入条目，也不会产生事件或通知。

## 3. 让内容进入事件

在同一分组的**监听**列新建监听。可以填关键词并选择“任意命中”或“全部命中”，也可以留空（不设关键词门槛）；按需填排除词、选择灵敏度。首次使用建议先用默认的纯算法模式，避免产生模型费用；如需 LLM+，先看[配置](configuration.md)的模型供应商和调用顺序。

发现按计划首次采集时会建立历史基线；**首次看到的旧条目不会因此产生通知**。等后续采集出现新内容、且监听判定通过，才会形成事件。手动“测试采集”也不是催生一次真实事件的方法。

## 4. 配置第一条投递

到**通知渠道**新建 Telegram 或 Webhook 渠道并保存，然后按需点渠道卡上的“测试”：这一步**会真正发送测试消息**。Telegram 需要 Bot token 与会话 ID；Webhook 需要接收地址，详见[配置](configuration.md)。

回到同一分组的**动作**列新建动作，选择“采集到就投递”或“每天汇总”、选已启用的通知渠道和消息模板，再保存。若选每天汇总，还需设置汇总时间。监听默认跟随分组里的动作；如果在监听里指定了关联动作，只有选中的动作会接收该监听的命中。

## 5. 确认结果

**仪表盘**展示真实统计、最近事件和异常。出现新内容后，先看发现是否完成了非首次采集，再看事件列表；如果有事件却没收到通知，再检查动作、渠道及异常记录。渠道测试成功只证明渠道能发一条测试消息，**不能证明发现、监听和动作整条链已经命中**。逐项检查路径见[使用手册](usage.md#为什么没有事件或通知)。
