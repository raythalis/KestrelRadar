# Kestrel 开发计划与工程规范

> 需求基线：[`requirements.md`](./requirements.md)（v1.0，已定版）。
> 本文件规定**怎么做**：阶段划分、目录与命名规范、验收方式、以及"不留死东西"的纪律。
> 计划调整时改本文件，改需求时改 `requirements.md`。

---

## 1. 铁的规矩

1. **一次只做当前阶段**，阶段结束停下交验收报告，等确认再进下一阶段。
2. **测试先行**：先写测试跑到失败，再实现到通过（RED → GREEN → REFACTOR）。
3. **不擅自扩大范围**：发现缺口先报告、等确认，不顺手实现；不提前做后续阶段的东西。
4. **改动即清理**：被替代的字段、开关、接口、类型、翻译 key、样式、依赖，在同一阶段内删掉，不留"以后可能有用"。
5. **最小改动 + 可回滚**：每阶段在 `develop` 上单独提交，能单独回退。
6. **不 push**：开发阶段本地提交即可，由作者决定何时交付到 `master`。

## 2. 阶段划分

每个阶段都以「能跑通 + 有实测数据」结束，不用"应该可以"当结论。

| 阶段 | 范围 | 明确不做 | 验收判据（要贴真实输出） |
|---|---|---|---|
| **M1 骨架与数据层** | monorepo 骨架、后端服务骨架、数据库 schema 与索引、配置类实体的读写接口（分组/发现/监听/动作/渠道/模型/设置）、前端只读接上接口 | 不做采集、判定、归并、通知 | 接口级测试全绿；真实建库成功；前端能把配置从接口读出来 |
| **M2 采集层** | 三类发现的抓取与解析、指纹去重、三个时间字段、首次建基线、每发现一个 cron 任务（照 MoviePilot 的 APScheduler 形态）、全局并发上限、超时与重试、两级连通性测试 | 不做判定、归并、通知（新鲜窗口是投递门槛，放 M4） | 用真实 RSSHub 实例跑真实路由，给出抓到条数 / 去重命中数 / 基线行为；故障隔离测试：故意让一个源失败，其余照常 |
| **M3 判定层** | 关键词门槛、打分三档、灵敏度、排除词与全局排除词、判定理由、规则预览、未命中内容可查 | LLM 只留接口，不接真实模型 | 用真实采集数据跑判定，给出命中/未命中清单与逐条理由；同输入同输出（可复现） |
| **M4 归并与投递** | 事件归并（同链接必并、相似内容保守并）、来源计数、幂等（内容 × 动作）、即时与汇总两种触发、新鲜窗口门槛、每日上限、状态机与「有更新」 | 先只做 Webhook 渠道，Telegram 放阶段末 | 用夹具构造多来源同一件事，验证归并结果与「不重复推」；真实发送动作留痕 |
| **M5 前端界面** | 配置管理三列（分组折叠、移动端标签切换）、通知渠道页、模型页、高级设置页、i18n、主题 | 不做仪表盘数据 | 关键流程实点一遍，附截图 |
| **M6 仪表盘与打包** | 仪表盘真实数据、结果列表与安全阀查询、打包形态落地、README 与使用文档 | — | 全新环境按文档跑通一遍 |

阶段内的顺序：**先把数据与接口做对，再做界面**。

## 3. 目录规范

单仓 monorepo，按"应用 / 共享包 / 文档 / 基础设施"四类分：

```
kestrel/
├── apps/
│   ├── web/                  # 前端（Vue 3 + Vuetify + TypeScript）
│   │   ├── public/           # 静态资源（设计稿放这里或 docs/design/）
│   │   └── src/
│   │       ├── api/          # 接口调用封装（每个资源一个文件）
│   │       ├── assets/       # 图片、字体
│   │       ├── components/   # 可复用组件（按领域分子目录）
│   │       ├── composables/  # 组合式函数
│   │       ├── layouts/      # 布局
│   │       ├── locales/      # 翻译文案（zh-CN / en-US）
│   │       ├── plugins/      # Vuetify、i18n 等插件装配
│   │       ├── router/       # 路由
│   │       ├── stores/       # Pinia
│   │       ├── styles/       # 全局样式与主题变量
│   │       ├── types/        # 仅前端使用的类型
│   │       ├── utils/        # 纯函数工具
│   │       └── views/        # 页面（路由直达）
│   └── api/                  # 后端（Node + TypeScript + Fastify + SQLite）
│       └── src/
│           ├── config/       # 启动配置与环境变量解析
│           ├── db/           # 连接、迁移、查询
│           ├── modules/      # 领域模块，一个领域一个目录
│           │   ├── groups/
│           │   ├── discoveries/
│           │   ├── monitors/
│           │   ├── actions/
│           │   ├── channels/
│           │   ├── models/
│           │   └── settings/
│           ├── plugins/      # Fastify 插件（错误处理、日志）
│           ├── routes/       # HTTP 路由，只做参数收敛与调用模块
│           ├── services/     # 跨模块服务（调度器等）
│           └── utils/
├── packages/
│   └── contracts/            # 前后端共享：类型 + Zod 校验 + 接口路径常量
├── docs/                     # 需求、计划、设计稿、使用文档
├── infra/                    # 部署相关（docker 等）
└── local/                    # 个人/本机专用（gitignore，不进远端）
```

规矩：
- **一个文件只做一件事**；模块目录下固定拆 `xxx.service.ts`（业务）、`xxx.repo.ts`（数据库）、`xxx.routes.ts`（HTTP）、`xxx.schema.ts`（校验）、`xxx.types.ts`（内部类型）。
- 跨前后端共享的类型与校验**只放 `packages/contracts`**，两端不许各写一份。
- 一次性的脚本、探针、旧代码放 `local/`，不进远端。

## 4. 命名规范

| 对象 | 规范 | 例子 |
|---|---|---|
| 目录、普通文件名 | 短横线小写 | `discovery-list.vue`、`monitor.service.ts` |
| Vue 组件文件 | 大驼峰 | `MonitorCard.vue` |
| 变量、函数 | 小驼峰 | `freshnessWindowDays`、`buildFingerprint()` |
| 类型、接口、类 | 大驼峰 | `MonitorRule`、`DiscoveryKind` |
| 常量 | 大写下划线 | `DEFAULT_CONCURRENCY` |
| 数据库表 | 小写下划线、复数 | `discoveries`、`monitor_hits` |
| 数据库列 | 小写下划线 | `first_seen_at`、`source_published_at` |
| 数据库索引 | `idx_<表>_<列>` | `idx_items_fingerprint` |
| HTTP 路径 | 小写复数、短横线 | `/api/monitors`、`/api/model-providers` |
| 查询参数 | 小驼峰 | `?deliveredOnly=true` |
| 环境变量 | 大写下划线、前缀 `KESTREL_` | `KESTREL_DB_PATH` |
| 事件类回调 | `on` + 大驼峰 | `onFetchFailed` |
| 布尔量 | `is` / `has` / `can` 开头 | `isEnabled`、`hasBaseline` |
| 时间字段 | 后缀 `_at`（数据）/ `At`（代码） | `last_seen_at`、`lastSeenAt` |
| 数量字段 | 后缀 `_count` / `Count` | `item_count`、`sourceCount` |
| 分支 | `feature/<阶段>-<短描述>` | `feature/m1-skeleton` |
| 提交 | `type(scope): 中文说明` | `feat(api): 增加分组读写接口` |

提交类型只用：`feat` / `fix` / `refactor` / `test` / `docs` / `chore`。

**命名一致性**：同一个概念全仓一个词，不做同义词轮换。固定词表：

- `group` 分组、`discovery` 发现、`monitor` 监听、`action` 动作、`channel` 渠道
- `item` 条目（采到的一条内容）、`event` 事件（归并后的）、`delivery` 投递
- `fingerprint` 指纹、`baseline` 基线、`freshness window` 新鲜窗口、`hit` 命中
- `sensitivity` 灵敏度、`keyword` 关键词、`exclude` 排除词、`intent` 意图描述

界面文案跟随产品用语（发现/监听/动作）；代码一律用上面的英文词。

## 5. 不留死东西的纪律

**目标**：不要再出现"当初加的配置项/参数，后来发现根本没用上"。

1. **加之前先找调用路径**：新增任何配置项、参数、字段、开关，必须同时有**读端和写端**（界面能改 + 代码真的读它）。做不到就先不加。
2. **改之前先找替代物**：用新字段/新接口替代旧的时，同一阶段内删掉旧的（含旧迁移、旧测试、旧文案、旧样式）——除非它承载历史数据，那就写一条数据迁移。
3. **每个阶段收尾做一次未使用项扫描**，把结果写进验收报告：
   - 未使用的配置键（每个键全仓搜索，确认有读取点）
   - 未使用的导出（函数/类型/常量）与依赖
   - 未使用的翻译 key、CSS 类、图片资源
   - 已废弃的路由、字段、表列（并给出迁移或删除结论）
4. **死于"以后可能有用"**：不写占位接口、不写暂时用不上的抽象层、不预埋没用上的配置项。
5. 阶段报告的固定格式（见第 7 节）里必须有**"本阶段删除了什么"**一栏，没有就写"无"。

## 6. 其他工程约定

- **代码风格**：Prettier（`singleQuote: true`、`semi: false`、`printWidth: 100`），ESLint 与 Prettier 同时跑；提交前必须过。
- **测试**：
  - 单元测试与接口级测试都写；涉及数据库的测试用临时库，不碰真实库。
  - 需要真实数据的地方用真实源（RSSHub 实例等），**不用 mock 数据糊弄验收**。
  - 每条需求至少对应一条测试；删功能时同时删它的测试。
- **定时与调度**：照 MoviePilot 的形态——每个发现注册成一个 cron 任务，由调度器自己持有下次触发时间并到点回调；不用「每分钟轮询谁到期」那种算法。任务表在启动时与每次配置变更后与发现表对齐（该建的建、频率变了换、停用或删除的撤销）。
- **数据库迁移**：每次结构变化写一条编号迁移脚本进仓库，可重复执行、可回滚；已冻结的 schema 语义不得改动，只允许加索引这类不影响语义的改动。
- **接口**：请求与响应都过 Zod 校验；错误统一结构（错误码 + 人话消息），不向调用方抛堆栈。
- **日志**：结构化、可读；不打印密钥、token、完整私密配置。
- **时间**：一律以 UTC 存库，界面按应用时区显示（见需求文档 3.2）。
- **安全**：密钥只存库里/环境变量，不写进代码与仓库；默认无登录，只在内网使用。

## 7. 阶段验收报告模板

```
阶段：M<N> <名称>
分支/提交：feature/mN-xxx @ <短哈希>

一、本阶段做了什么（逐条）
二、实测结果（真实命令输出：测试通过数、真实数据条数、耗时）
三、本阶段删除了什么（被替代/未使用项）
四、未使用项扫描结果
五、已知限制与缺口（不掩盖）
六、是否可冻结 + 下一阶段的建议
```

结论只有两种：**可冻结** 或 **不可冻结（附原因）**。
